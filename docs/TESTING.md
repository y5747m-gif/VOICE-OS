# اختبار VOICE OS · MVP 0.2.0

## ما تم التحقق منه بالفعل

| الفحص | الحالة |
|---|---|
| Kotlin/JVM 2.1.21 + Java 17: `scripts/check-core.sh` | **نجح.** 17 حالة مطابقة و21 حالة رفض، وعدم إرسال مدخل مرفوض للمحوّل، ونقل نتيجة فشل/بطارية من الأداة دون تغيير، والإلغاء قبل التسليم. نفس الاختبار نجح أيضًا بتشغيل JUnitCore مباشرة. وتم فحص 28 عبارة من كتالوج اللغتين ومطابقتها بالإجراءات المعلنة. اجتاز كمان عقود رابط HTTPS والإصدار وشهادة التوقيع. |
| موارد AR/EN وبيان التطبيق: `python3 scripts/check-resources.py` | **نجح.** اتفاق مفاتيح اللغتين ووسائط التنسيق وإذن الميكروفون و`INTERNET` لفحص إصدار الموقع فقط في البيان الرئيسي. |
| AAPT2 | **نجح** تجميع وربط موارد التطبيق وبيان المصدر مقابل Android API 36 في فحص مستقل. ناتج هذا الفحص ليس APK قابلًا للتثبيت. |
| ترجمة مصادر Kotlin/Compose والاختبارات | **نجحت** ضد API 36 ولقطة مكتبات AndroidX من AOSP باستخدام Compose compiler 2.1.21؛ ليس بديلًا عن بناء Gradle بالإصدارات المثبتة في المشروع أو عن توليد Room بـ KSP. |
| Gradle: `assembleDebug` و`lintDebug` وتوليد Room | **لم يكتمل في بيئة العمل الحالية:** Gradle Wrapper لم يستطع تنزيل التوزيعة بسبب تقييد الشبكة. |
| التثبيت وتشغيل الميكروفون والنطق والـ Intents على جهاز | **لم يُختبر هنا.** لا جهاز Android أو محاكٍ متاح في بيئة العمل. |

## فحص التثبيت والتحديث

- الويب: `npm test` (17 اختبارًا) و`npm run build` نجحا بعد ربط Groq. اختبارات Groq تستخدم بدلًا اختباريًا ولا تتصل بمزوّد حقيقي؛ تتحقق من حماية المفتاح، ومسارات الحالة والتفريغ والتصنيف، وحدود الطلبات والنتيجة المحصورة في كتالوج المواقع. تعذر تشغيل `npm run test:pwa` في هذه البيئة لأن Chromium الخاص بـ Playwright غير مثبت؛ يحتاج تثبيت المتصفح ثم إعادة الفحص. اختبارات تنزيل APK تستخدم ملفات اختبار فقط.
- أداة `release:android`: استُخدم `apksigner` الحقيقي لمراجعة حزمة اختبار موقّعة. فحص الرفض مع بصمة مختلفة أو `versionCode` مكرّر؛ لم يُنتج ذلك ملف VOICE OS قابلًا للتوزيع.
- على جهاز قبل التوزيع: ثبّت بناء `release` موقّعًا، احفظ عنوان الموقع النهائي، وانشر بناء أحدث بنفس المفتاح ورقم أعلى. اختبر الفحص والتنزيل وتأكيد Android وبقاء الإعدادات بعد التحديث. جرّب غياب ملف، عنوان HTTP/مسار غلط، فصل الشبكة، وإصدار موقّع بشهادة مختلفة؛ لا ينبغي ظهور زر تنزيل غير صالح. لا تتجاوز أي تحذير من مصدر غير موثوق.
- على هاتف فعلي: افتح الإنتاج في Chrome على Android وفي Safari على iPhone وثبّت من قائمة المتصفح. افصل الشبكة بعد التحميل الأول وافتح من الأيقونة، ثم أعد الاتصال واختبر تحديث بناء الموقع. **هذا الاختبار على الهاتف والتثبيت الفعلي للـ APK لم يُشغَّلا هنا.**

## الفحوص المرفقة في المستودع

- `:core:test` يشغّل نفس عقود المحلل والتنفيذ في JUnit. الاختصار اليدوي لا يدخل أي وجهة إلا من `DeviceAction`. المدخلات المركبة أو المحمية أو خارج القواعد لا تبعث أي Intent.
- `:app:connectedDebugAndroidTest` يفحص عبارات كتالوج التطبيق في اللغتين، رفض التنفيذ من غير Activity واجهة، إدراج Room وحدّ السجل ومسحه، واستخدام شاشة المساعد لقراءة البطارية فعليًا أو لعرض سبب عدم التوفر، ثم رفض طلب إرسال غير مدعوم.
- مسار CI في `.github/workflows/android.yml` يبني APK التطوير ويفحص Lint والبيان النهائي، ويُشغّل Instrumentation على محاكي `API 35` عند اختيار `emulator` في تشغيل يدوي. لا تفترض نجاحه قبل تشغيله.

## تشغيل بوابة القبول محليًا

راجع [متطلبات البناء](../README.md#البناء-والتشغيل). مع SDK وجهاز أو محاكي مفتوح:

```bash
./gradlew :core:test :app:lintDebug :app:assembleDebug :app:connectedDebugAndroidTest
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

استخدم Debug جديدًا على محاكي للاختبارات الآلية. اختبر الميكروفون وTTS على هاتف حقيقي أيضًا؛ صور Android الخام أحيانًا لا تحتوي على RecognitionService أو أصوات اللغة. لا تثبّت تطبيقات إضافية فقط لاستيفاء اختبار «غير متاح». توفر الصوت يختلف حسب حزم الجهاز وإصداره والمزوّد.

## مصفوفة الاختبار اليدوي

| السيناريو | الخطوة | النتيجة المتوقعة |
|---|---|---|
| بداية بخصوصية | افتح التطبيق أول مرة وانتظر. | RTL افتراضي، لا يبدأ الميكروفون ولا يظهر طلب إذن تلقائي، والسجل فارغ. |
| قراءة البطارية | اكتب `البطارية كام؟` ثم `Check battery level`، وقارن بقراءة الهاتف. | نفس المسار؛ نسبة حقيقية أو رسالة عدم توفر من Android. |
| إعدادات Android | اكتب `افتح إعدادات الواي فاي`. ارجع للتطبيق. | صفحة Wi‑Fi أو رد صريح لو مفيش وجهة، من غير تغيير Wi‑Fi. رد الفتح لا يدّعي التحكم في الشاشة. |
| تطبيق موجود / غائب | نفّذ `افتح يوتيوب` إذا مثبت ثم جرّب تطبيقًا مدعومًا غير مثبت. | طلب فتح حقيقي للأول؛ رد «ملقاش تطبيق متاح» للثاني، من غير تحويل صامت للمتجر أو موقع. |
| لوحة الاتصال والكاميرا | استخدم الاختصار أو كتالوج الأوامر. | تفتح الواجهة إن توفرت؛ لا مكالمة أو التقاط صورة تلقائي. |
| أوامر غير مسموحة | اكتب `افتح واتساب وابعت لمحمد إني هتأخر شوية` و`شغّل الواي فاي`. | لا Intent، ولا إجراء جزئي أو ادعاء بالإرسال. |
| إذن الميكروفون | اضغط عليه وارفض الإذن؛ اكتب أمرًا؛ أعد تمكين الإذن من صفحة الصلاحيات. | الصوت موقوف عند الرفض؛ الكتابة تشتغل؛ الإذن لا يبدأ الاستماع من صفحة الصلاحيات. |
| مزوّد الصوت | جرّب بدون تعرّف محلي. افتح الإعدادات وفعّل مزوّد Android بعد التأكيد، ثم أعد إيقافه. | رسائل مفهومة وبديل كتابة، لا انتقال صامت، وإعداد المزوّد قابل للرجوع. |
| بداية/نهاية الكلام | على هاتف بلغة تدعمها الخدمة قول `افتح الكاميرا`، مرة بانتهاء الكلام ومرة بـ«خلصت كلام». | مراحل الاستماع والنص إن أرسله المزوّد، موجة ترتبط بمستوى الصوت المتاح، تنفيذ مرة واحدة من النتيجة النهائية. |
| صمت/لغة | جرّب صمتًا أو ضوضاء، ولغة غير مثبتة عند توفر المزوّد. | خطأ أو مهلة بلا تنفيذ؛ الكتابة وإعادة المحاولة متاحتان. |
| إلغاء | أثناء الكلام اضغط «إيقاف»، وكرّر بخروجك من التطبيق قبل نهاية الكلام. | يتوقف مؤشر الميكروفون، ولا يُنفذ أمر إذا لم يُسلّم إلى Android؛ رجوع التطبيق لا يعيد الطلب. |
| نطق | فعّل صوتًا محليًا للجهاز، نفّذ أمر البطارية، أعد النطق وأوقفه. جرّب لغة بلا صوت محلي. | رد نصي مع نطق عندما يتوفر، وزر إيقاف؛ لا تنزيل أو مزوّد شبكة تلقائي في حالة غياب الصوت. |
| الاسم والاختصارات | احفظ اسمًا من الذاكرة، أعِد التشغيل، امسحه بعد تأكيد. أضف/أزل اختصارًا، وجرب حد الثلاثة. | الترحيب والتثبيت يتغيران، ونتيجة الاختصار ليست مكتوبة مسبقًا. لا صلة بجدولة الأوامر. |
| سجل اختياري | نفّذ أمرًا قبل التفعيل وبعده. اقفل العملية وأعد الفتح، أوقف الحفظ ثم امسح بعد تأكيد. | فقط الإجراء المنظّم بعد التفعيل يظهر من Room. إيقاف الحفظ لا يمسح السابق؛ المسح يزيل السجل والمحادثة الحالية. |
| الشكل والوصول | بدّل عربي/English وداكن/فاتح، كبّر الخط وجرّب TalkBack ولوحة مفاتيح ظاهرة. | اتجاه ملائم، تباين وقراءة للنص، أزرار واضحة ومتاحة، لا تنفيذ لمجرد التنقل أو تدوير الشاشة. |

**بوابة المرحلة الثانية:** بناء APK بالـ Gradle بإصدارات المشروع، نجاح الاختبارات، وتجربة حقيقية للتعرّف والنطق على جهاز مدعوم والتحقق من الإيقاف. لو تعذر التعرّف بسبب جهاز أو لغة، وثّق المسار البديل بدل اعتماد الصوت على أنه اختُبر.

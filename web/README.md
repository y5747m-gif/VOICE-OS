# VOICE OS Web

تطبيق ويب قابل للتثبيت (PWA)، بتصميم مستوحى من مرجع المستخدم: زجاج وردي ولاڤندر، موجة لامعة، وميكروفون مركزي. تدعم العربي المصري RTL والإنجليزي. الواجهة تفتح **المواقع الرسمية** فقط، وما بتتحكمش في إعدادات الموبايل أو تبعت رسائل. نفس الموقع يقدر يستضيف إصدار Android الموقّع؛ مفيش مزامنة للصوت أو السجل أو الحسابات بين النسختين.

## التشغيل

```bash
cd web
npm ci                    # Node.js 22+
npm run dev                # 5173: الواجهة وAPI الصوت من نفس الخادم
npm test                   # الأوامر والصوت وعقد إصدار Android
npm run build && npm start  # خادم الإنتاج المحلي (PORT، افتراضيًا 4173)
```

جرّب `افتح يوتيوب` من خانة الكتابة. هتشوف الوجهة قبل ما تختار «افتح الموقع». الميكروفون يعتمد على `SpeechRecognition` في المتصفح؛ لو ما اشتغلش في إطار المعاينة، افتحها في تبويب مستقل بمتصفح مدعوم وعبر HTTPS. الأوامر المكتوبة والاختصارات تفضل متاحة.

## التثبيت على الموبايل وتحديث الويب

1. افتح **نسخة الإنتاج عبر HTTPS** في المتصفح. لو بتجرب من المعاينة، افتحها في تبويب مستقل؛ العنوان المؤقت مش مناسب لتوزيع نسخة دائمة. `npm run dev` لا يسجّل عامل خدمة.
2. اضغط **ثبّت التطبيق** في الموقع. على **Android** استخدم «ثبّت من المتصفح» لو ظهرت، أو من قائمة Chrome اختر «تثبيت التطبيق» / «إضافة إلى الشاشة الرئيسية». على **iPhone** استخدم Safari ← مشاركة ← إضافة إلى الشاشة الرئيسية. نسختا الويب من نفس الموقع؛ ملف `APK` يخص Android فقط.
3. المتصفح يحمل ملفات الواجهة. بعد أول تحميل ناجح، الواجهة والكتابة ومعاينة الأوامر تشتغل من الذاكرة المؤقتة حتى من غير إنترنت، لكن فتح المواقع، وفحص إصدار Android، والصوت السحابي محتاجين اتصال. بيانات الإصدار وملف APK وطلبات الصوت لا تتخزن في عامل الخدمة.
4. بعد نشر بناء جديد على **نفس العنوان**، المتصفح يفحصه عند الفتح أو الرجوع للتطبيق. للفحص اليدوي اختَر **ثبّت التطبيق ← تحديث تطبيق الموقع ← افحص التحديثات**. لو النسخة الجديدة جاهزة والجلسة مفتوحة، اختَر **حدّث وافتح من جديد**؛ ده يعيد فتح الواجهة ويمسح سجل الجلسة المؤقت. مفيش تثبيت APK في الخطوة دي.

للتوزيع: شغّل خادم الإنتاج خلف HTTPS بعنوان ثابت على جذر النطاق (`/`)، ومرّر مسارات `/api/` و`/downloads/` لنفس خادم Node. انشر ناتج `npm run build` كاملًا كعملية واحدة، مش ملفات متفرقة. لا تفعّل تخزينًا طويلًا لـ `/sw.js` أو HTML أو مسارات إصدار Android في الوكيل/CDN؛ الأصول ذات الأسماء الممهورة بهاش فقط طويلة التخزين. لو تنشر على عدة نسخ خادم، استخدم نفس البناء ونفس بيانات إصدار Android فيها كلها.

## نشر APK وربطه بالموقع

رابط **نزّل APK** يظهر بس لما ملف موقّع ومنشور موجود على الموقع؛ خلاف كده تظهر رسالة واضحة. لم يتم نشر APK في المعاينة. على Android ثبّت الإصدار الأول من الموقع، ثم من **الإعدادات ← الموقع والتحديثات** احفظ عنوانه واضغط **افحص التحديثات**. عند وجود إصدار أحدث بنفس شهادة التوقيع، اضغط **نزّل من المتصفح**. افتح الملف بعد انتهاء التنزيل ووافق في شاشة Android. قد يطلب Android الإذن للمتصفح كمصدر تثبيت؛ التطبيق نفسه لا يطلب صلاحية تثبيت ولا يحاول التثبيت تلقائيًا.

**خطوات الناشر:** تحتاج بناء Android كامل حسب [README المشروع](../README.md#البناء-والتشغيل)، وخادم HTTPS ثابت، ومفتاح توقيع خاص بإصدارات `ai.voiceos`. حافظ على نفس مفتاح الإصدارات مع نسخة احتياطية آمنة؛ APK التطوير أو إصدار بتوقيع مختلف مش ممكن يستبدل النسخة المثبّتة. لو بتوزع عبر متجر بيعيد التوقيع، المسار ده لا يحدّث نسخة موقّعة بشهادة مختلفة.

1. من جذر المشروع، ابنِ إصدار `release` بعد اختبار نسخة التطوير. `voiceOsSiteUrl` اختياري: لو مش محدد، المستخدم يضيف العنوان يدويًا. استخدم عنوان الإنتاج مش عنوان المعاينة. زوّد `voiceOsVersionCode` في **كل** تحديث؛ `versionName` للعرض:

   ```bash
   ./gradlew :core:test :app:lintRelease :app:assembleRelease \
     -PvoiceOsSiteUrl=https://voice.example.org \
     -PvoiceOsVersionCode=2 -PvoiceOsVersionName=0.2.0
   ```

2. وقّع الـ APK بمفتاح الإصدار على جهاز موثوق. تقدر تستخدم Android Studio أو Build-Tools على Linux/macOS. المثال يفترض إن `RELEASE_KEYSTORE` يشير لملف مفتاح خاص خارج المستودع، و`RELEASE_ALIAS` هو اسم المفتاح، و`ANDROID_HOME` مسار SDK. خلّي `apksigner` يطلب كلمة المرور تفاعليًا؛ لا تحطها في سطر الأوامر أو ملفات `.env`:

   ```bash
   SDK_TOOLS="$ANDROID_HOME/build-tools/35.0.0"
   WORK="$(mktemp -d)"
   "$SDK_TOOLS/zipalign" -P 16 -f 4 \
     app/build/outputs/apk/release/app-release-unsigned.apk "$WORK/aligned.apk"
   "$SDK_TOOLS/apksigner" sign --ks "$RELEASE_KEYSTORE" --ks-key-alias "$RELEASE_ALIAS" \
     --out "$WORK/voice-os-release.apk" "$WORK/aligned.apk"
   "$SDK_TOOLS/apksigner" verify --print-certs "$WORK/voice-os-release.apk"
   ```

3. اضبط `ANDROID_RELEASE_DIR` لمسار خاص بالخادم، مثل `/srv/voiceos/releases`، خارج مجلد `dist`. اضبط `ANDROID_SIGNER_SHA256` لبصمة SHA‑256 لشهادة الإصدار **الموثوق بها** (64 خانة hex، من `Signer #1 certificate SHA-256 digest` بعد مراجعة أول إصدار). البصمة عامة؛ مفتاح التوقيع لا ينتقل للخادم. على جهاز نشر موثوق شغّل الأمر التالي مع `ANDROID_SIGNER_SHA256` في البيئة أو `web/.env.local`. لو Build-Tools في مسار مختلف استخدم `ANDROID_BUILD_TOOLS_DIR`:

   ```bash
   cd web
   npm run release:android -- "$WORK/voice-os-release.apk" /srv/voiceos/releases
   npm run build && npm start
   ```

   أداة النشر تتحقق بـ `apksigner` و`aapt2`، ترفض توقيعًا أو معرّفًا مختلفًا ونسخة تطوير/اختبار، وتشترط زيادة `versionCode` فوق المنشور. تضع `voice-os-<versionCode>.apk` من غير استبدال ملف سابق، ثم تحدث `release.json` ذريًا. احتفظ ببيانات الإصدار السابق في مجلد النشر وقت إصدار أي تحديث. لو جهاز البناء منفصل عن النشر، انقل APK الموقّع فقط واستخدم أداة النشر في بيئة عندها نفس أدوات التحقّق؛ لا تنقل ملف المفتاح معها. بعد تهيئة الخادم أول مرة، تغيير حزمة Android المنشورة لا يحتاج إعادة بناء الويب.

4. جرّب `GET /api/android/release` على العنوان النهائي ومعه رابط `/downloads/voice-os-<versionCode>.apk`. الخادم يتحقق من البصمة المعلنة وحجم وSHA‑256 للملف المنشور، مع دعم التنزيل الجزئي. `apksigner` يتحقق من التوقيع عند النشر، وAndroid يتحقق منه وقت التثبيت. لو اتغير آخر إصدار بين الفحص وفتح الرابط، افحص التحديث تاني للحصول على الرابط الجديد. اختبر تثبيت إصدار وتحديثه فعليًا على جهاز قبل توزيعه.

## صوت ElevenLabs المطلوب

الصوت المربوط: [Suhair Al Abtah](https://elevenlabs.io/voices/ML7jGRDg4E9hIl5qEm1Z)، المعرّف `ML7jGRDg4E9hIl5qEm1Z`. افتح الرابط لسماع عينته عند المزوّد. نستخدم نموذج `eleven_multilingual_v2` للنطق؛ اللغة العربية في الخدمة لا تضمن نفس اللهجة في كل رد.

1. استخدم مفتاح ElevenLabs من حساب عنده صلاحية **Text to Speech** ووصول لهذا الصوت. حسب [دليل Voice Library](https://elevenlabs.io/docs/eleven-creative/voices/voice-library)، أصوات المكتبة غير متاحة عبر API في الخطة المجانية.
2. انسخ `web/.env.example` إلى `web/.env.local` واضبط `ELEVENLABS_API_KEY`، أو اضبط المتغير مباشرة في أسرار خادم النشر. لا تستخدم بادئة `VITE_` أو `VOICE_PUBLIC_` للمفتاح، ولا تضعه في الكود أو المحادثة. أعد تشغيل الخادم بعد تعديل الإعداد.
3. افتح **إعدادات الصوت** ← **صوت سهير من ElevenLabs** ← وافق، ثم اضغط **جرّب الصوت**. الخادم يحتاج اتصال HTTPS بـ `api.elevenlabs.io`. حالة «المفتاح مضاف» تعني أنه موجود فقط؛ تجربة الصوت تتحقق من صلاحية الحساب وإمكانية الاتصال.

من غير المفتاح، لا يدّعي الموقع تشغيل صوت سهير. تقدر تختار الرد المكتوب أو صوت الجهاز المحلي إن كان متاح للغة. الخادم لا يقبل نصوصًا حرة للنطق: الواجهة تبعت معرف رد وإجراء مدعوم، والخادم يولّد منه جملة جاهزة. لا يُرسل تسجيل الميكروفون أو نص الأمر لـ ElevenLabs. خدمة تعرّف المتصفح قد تعالج الصوت عبر الإنترنت، زي ما بيتوضح قبل بدء الاستماع. سجل الفتح مؤقت داخل الصفحة، ويسهل مسحه.

للنشر الخارجي استخدم HTTPS، وحافظ على ترويسة `Host` العامة عند الوكيل العكسي. ضع وصولًا مصادقًا عليه وميزانية استخدام أمام مسار الصوت عند نشر مفتاح مدفوع؛ التحقق من الطلبات ومحدد المعدل داخل هذا الـ MVP ليسا مصادقة مستخدمين.

## التحقق

- `npm test` و`npm run build` اجتازوا الفحص. الاختبارات تتحقق من عقد الصوت باستخدام بدل اختباري ومن رد الموقع مع وبدون ملف APK، وحدود المسارات، ورفض ملف تالف أو بصمة مختلفة، والتنزيل الجزئي. اختُبرت أداة النشر منفصلًا على حزمة اختبار موقّعة بمفتاح مؤقت، مش على APK المنتج.
- جُرّب في Chromium على هاتف/سطح مكتب (محاكاة أحجام الشاشة): العربي والإنجليزي، الكتابة، عرض الوجهة، فتح تبويب بعد الموافقة، رفض الطلب غير المسموح، مسح السجل، وحالة الصوت بدون مفتاح. تم اختبار انتقالات التعرّف باستخدام بديل اختباري للـ Web Speech API، مش تسجيل من ميكروفون فعلي.
- لم تُستدعَ خدمة ElevenLabs بمفتاح فعلي في بيئة المعاينة. نجاح توليد الصوت الحقيقي يحتاج الخطوات أعلاه.
- لفحص الويب القابل للتثبيت: `npx playwright install chromium` ثم `npm run build && npm run test:pwa` من `web/`. نجح في Chromium: أهلية التثبيت، أبعاد الأيقونات، الواجهة من الذاكرة المؤقتة بدون شبكة، ظهور زر APK من ملف اختبار فقط، وانتظار التحديث وتطبيقه بعد الاختيار. ده لا يثبت تثبيتًا من شاشة هاتف فعلي أو اختبار Safari على iPhone.
